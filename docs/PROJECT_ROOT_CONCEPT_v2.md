# PROJECT ROOT — Game Concept

## 1. 한 줄 정의

**PROJECT ROOT**는 브라우저 안에서 하나의 가상 컴퓨터와 인터넷을 직접 사용하며 사건을 조사하는 웹 기반 사이버 미스터리 게임이다.

플레이어는 단순히 정해진 버튼을 누르는 것이 아니라, 게임 속 OS의 브라우저·터미널·메일·파일·사건 관리 앱 등을 직접 사용해 단서를 찾고 연결한다.

> 핵심 원칙: 게임은 **무엇을 조사해야 하는지**는 알려주지만, **정확히 어떻게 찾아야 하는지**까지 바로 알려주지 않는다.

---

## 2. 프로젝트명

- 게임명: **PROJECT ROOT**
- 한글 표기: **프로젝트 루트**
- 표기 예시: `PROJECT ROOT`, `ROOT`, `ROOT // INTERNAL`

`ROOT`는 컴퓨터 시스템의 최상위 권한과 시스템의 근원이라는 이미지를 동시에 가진다. 이야기에서는 사건의 근원을 추적한다는 의미와 더 깊은 비밀 시스템을 암시하는 의미를 함께 사용할 수 있다.

---

## 3. 핵심 분위기

- 현실적인 현대 데스크톱 OS
- 깔끔하고 차가운 기업용 소프트웨어 디자인
- 과도한 네온/Matrix식 '해커 UI' 지양
- 평범한 업무 환경 속에서 조금씩 이상함이 드러나는 분위기
- 처음에는 사이버 조사 업무처럼 시작하지만, 플레이할수록 자신이 속한 시스템 자체를 의심하게 됨

게임 초반에는 플레이어가 정상적인 사이버 조사 조직에 합류했다고 믿게 한다. 세계관의 진짜 정체는 시작 화면에서 설명하지 않는다.

---

## 4. 게임의 핵심 구조

게임 전체가 웹사이트에서 실행된다.

웹사이트 안에는 실제 데스크톱처럼 동작하는 가상 OS가 존재한다.

주요 앱 예시:

- 사건/정보 관리 앱
- 웹 브라우저
- 터미널
- 메일
- 파일 관리자
- 설정
- 메모 또는 텍스트 뷰어

향후 게임 내부 인터넷에는 검색 엔진, 회사 홈페이지, 개발자 프로필, 커뮤니티, 코드 저장소, 뉴스, 개인 사이트 등 다양한 가상 웹사이트를 구축한다.

모든 보안/침투 관련 상호작용은 게임 내부의 가상 시스템과 샌드박스 안에서만 이루어진다.

---

## 5. 사건 관리 앱

OS에서 가장 중요한 기본 앱이다.

단순한 튜토리얼 앱과 메모 앱을 따로 두지 않고 하나의 앱에서 사건 진행과 플레이어가 발견한 정보를 관리한다.

초기 구성안:

### CASE
현재 사건과 목표를 보여준다.

예:

- 대상의 최근 온라인 활동 확인
- 관련 계정 식별
- 이상 활동의 출처 조사
- 증거 정리

목표는 방향만 알려주며 구체적인 해결 절차는 알려주지 않는다.

### INTEL
플레이어가 발견한 정보를 정리한다.

예:

- 인물
- 사용자명
- 이메일
- 도메인
- IP
- 메모

중요한 정보가 전부 자동 등록되지는 않는다. 플레이어가 무엇이 중요한지 판단하도록 한다.

### ACCOUNTS
게임에서 발견한 계정을 저장한다.

예:

- 서비스
- 사용자명
- 게임 내부 자격정보
- URL
- 메모

### EVIDENCE
로그, 문서, 파일 등 사건 해결에 사용할 증거를 정리한다.

### HINT
막혔을 때 단계별 힌트를 제공한다.

힌트는 가능하면 다음 순서로 강해진다.

1. 생각해야 할 방향
2. 찾아볼 위치 또는 정보 종류
3. 명확한 다음 조사 지점

---

## 6. 터미널

터미널은 미션별 정답 입력창이 아니라 작은 가상 운영체제처럼 동작해야 한다.

장기적으로 지원할 명령 예시:

`whoami`, `hostname`, `pwd`, `ls`, `cd`, `cat`, `clear`, `echo`, `history`, `grep`, `find`, `head`, `tail`, `ping`, `ip`, `curl`, `wget`, `ssh`, `nslookup`, `dig`

명령 결과를 사건마다 하드코딩하기보다 가상 파일 시스템과 가상 네트워크의 상태에 따라 동일한 명령이 일관되게 작동하도록 설계한다.

---

## 7. 브라우저

브라우저는 단순히 미션 페이지를 여는 메뉴가 아니라 게임의 핵심 탐색 도구다.

장기적으로는:

- 주소창
- 검색
- 탭
- 방문 기록
- 북마크
- 게임 내부 웹사이트

등을 지원한다.

게임과 관계없는 검색어를 입력했다고 무조건 `INVALID QUERY`를 띄우는 방식은 지양한다. 게임 세계의 인터넷이 실제 인터넷처럼 넓게 느껴지는 것이 목표다.

---


# 8. 현실 서비스 ↔ PROJECT ROOT 구현 서비스 대조표

게임 속 인터넷은 현실 서비스를 그대로 복제하지 않고, 플레이어가 역할을 직관적으로 이해할 수 있는 **독자적인 가상 서비스**로 구성한다. 아래 이름은 기능과 세계관을 잡기 위한 작업명이며, 추후 브랜딩 과정에서 변경할 수 있다.

| 현실의 서비스/개념 | PROJECT ROOT 구현 서비스 | 게임 내 역할 |
|---|---|---|
| Google | **Index** | 기본 검색 엔진. 인물, 회사, 도메인, 뉴스, 게시물 등을 찾는 출발점 |
| Chrome / Firefox / Safari | **Browser** *(명칭 미정)* | 게임 내부 웹과 검색 엔진을 탐색하는 기본 브라우저 |
| Gmail / Outlook | **Mail** | 사건 의뢰, 내부 연락, 외부 인물과의 메일, 첨부파일 확인 |
| GitHub / GitLab | 유지 | 개발자 프로필, 저장소, 커밋, 이슈, 코드 및 노출된 단서 조사 |
| LinkedIn | **Profile** *(명칭 미정)* | 인물의 직장, 경력, 동료 관계와 공개 프로필 조사 |
| Reddit / 포럼 | **Threads** | 사용자 게시물, 댓글, 소문, 기술 질문 등 공개 커뮤니티 조사 |
| X / SNS | **Feed** *(명칭 미정)* | 짧은 공개 게시물과 인물의 최근 활동 추적 |
| Google Drive / Dropbox | **Cloud** | 공유 문서, 파일, 폴더 및 사건 관련 자료 열람 |
| Google Maps | **Maps** *(추후)* | 회사·시설·사건 관련 위치 조사 |
| 뉴스 포털 | **Wire** | 기업 발표, 사건 기사, 과거 기록 검색 |
| WHOIS / DNS 조회 서비스 | **Lookup** | 게임 내부 도메인의 등록·DNS·네트워크 정보 조사 |
| SSH / 원격 서버 | **Terminal / SSH** | 허가된 게임 내부 가상 서버 접속 및 조사 |
| Windows Terminal / macOS Terminal | **Terminal** | 가상 파일 시스템과 네트워크를 명령어로 탐색 |
| Finder / File Explorer | **Files** | 다운로드 파일, 사건 자료, 로그, 문서 관리 |
| 메모 / 사건 관리 도구 | **Cases** | CASE, INTEL, ACCOUNTS, EVIDENCE, HINT를 통합 관리 |
| 1Password / 비밀번호 관리자 | **Cases → Accounts** | 플레이 중 발견한 게임 내부 계정과 관련 메모 저장 |
| OS 설정 | **Settings** | 사용자 프로필, 테마, 배경, 시스템 환경 설정 |

### 구현 원칙

- 현실 서비스의 로고·UI·브랜드를 그대로 복제하지 않는다.
- 기능은 익숙하게 느껴지되 PROJECT ROOT만의 서비스명과 디자인을 사용한다.
- 가상 서비스들은 서로 독립된 미션 화면이 아니라 **하나의 인터넷에 존재하는 것처럼 연결**한다.
- 같은 인물의 username, email, 회사명, 도메인 등이 여러 서비스에 걸쳐 자연스럽게 이어질 수 있어야 한다.
- 플레이어가 주소를 직접 입력하거나 검색 결과를 따라 이동하면서 새로운 서비스를 발견할 수 있게 한다.
- 모든 침투·계정·네트워크 상호작용은 PROJECT ROOT 내부의 허구 시스템과 샌드박스에서만 처리한다.

> 목표는 “Google의 가짜 버전, GitHub의 가짜 버전”을 만드는 것이 아니라, 현실 인터넷에서 익숙한 정보 탐색 방식을 PROJECT ROOT의 독자적인 인터넷 생태계로 재구성하는 것이다.

# 9. 최초 사용자 경험 — 이번 구현 범위

이번 첫 구현에서는 실제 사건 플레이까지 만들지 않는다.

구현 범위는 아래 흐름까지다.

```text
Landing Page
    ↓
게임 소개
    ↓
START
    ↓
세계관 인트로
    ↓  Enter
다음 문장/화면
    ↓  Enter
...
    ↓
시작하기
    ↓
PROJECT ROOT 계정 생성
    ↓
가상 컴퓨터 부팅
    ↓
초기 OS 등록/설정
    ↓
Desktop
    ↓
사건 관리/안내 앱 자동 실행
```

---

## 10. 랜딩 페이지

처음 사이트에 접속했을 때 게임을 바로 OS 화면으로 보내지 않는다.

PROJECT ROOT 자체를 소개하는 랜딩 페이지가 먼저 나온다.

필수 요소:

- PROJECT ROOT 로고/워드마크
- 짧은 게임 설명
- 게임의 핵심 특징
- `시작하기` 버튼

설명은 스포일러 없이 작성한다.

예시 방향:

> 브라우저 너머의 흔적을 추적하라.  
> 웹, 터미널, 파일과 기록을 직접 탐색하며 사건의 근원을 찾아가는 사이버 미스터리.

정확한 카피는 UI 제작 과정에서 다듬을 수 있다.

---

## 11. 세계관 인트로

랜딩 페이지의 시작하기를 누르면 짧은 인터랙티브 인트로가 시작된다.

일반적인 긴 설명문 페이지보다는 검은색 또는 어두운 화면에서 짧은 문장들이 단계적으로 등장하는 방식이 적합하다.

- Enter 또는 화면 버튼으로 다음 단계 진행
- 텍스트가 한 번에 너무 많이 나오지 않도록 구성
- 조직의 진짜 목적이나 후반 반전은 공개하지 않음
- 플레이어가 새로운 시스템/조직에 들어간다는 사실만 자연스럽게 전달

마지막 단계에서 명확한 `시작하기` 버튼이 나타난다.

---

## 12. 계정 생성

게임 서비스 계정과 게임 속 PC 사용자 계정을 **하나로 통일한다.**

따라서 가입 과정에서 만든 사용자 정보가 OS에도 그대로 사용된다.

최소 입력값:

- Username
- Email
- Password
- Password confirmation

가입 완료 후 별도의 두 번째 PC 사용자 계정을 다시 만들게 하지 않는다.

OS에서 예를 들어 다음과 같이 활용할 수 있다.

```text
Username: jihan
Email: example@example.com
Home: /home/jihan
Terminal: jihan@root:~$
```

실제 서비스 구현 시 비밀번호는 평문으로 저장하지 않는다.

---

## 13. 첫 부팅

가입 직후 가상 컴퓨터가 처음 켜지는 연출을 보여준다.

일반 웹 로딩 스피너보다 실제 컴퓨터 부팅에 가까운 연출을 목표로 한다.

예시 흐름:

```text
PROJECT ROOT

Initializing workspace...
Loading user profile...
Connecting services...
Preparing desktop...
```

이후 OS 초기 설정 화면으로 전환한다.

계정 정보는 이미 가입 과정에서 확보했으므로 사용자명과 이메일을 다시 입력시키지 않는다.

초기 설정에서는 향후 다음과 같은 항목을 받을 수 있다.

- 표시 이름 확인
- 테마/배경 등 기본 환경 설정
- 약관 또는 보안 안내

MVP에서는 이 과정을 짧게 유지한다.

---

## 14. 첫 Desktop

설정이 끝나면 처음으로 PROJECT ROOT의 가상 OS 데스크톱이 나타난다.

화면 구성 예시:

- 바탕화면
- 상단 또는 하단 시스템 바
- 시간
- 네트워크 상태
- 사용자 메뉴
- 앱 아이콘

초기 앱 아이콘 예시:

- Cases
- Browser
- Terminal
- Mail
- Files
- Settings

처음 진입했을 때는 **사건 관리/안내 앱을 자동 실행한다.**

이 앱에서 플레이어에게 환영 메시지와 기본적인 조작법을 보여주고, 이후 첫 번째 사건을 전달하는 구조로 확장한다.

이번 구현에서는 첫 사건 전체를 만들 필요는 없다. Desktop과 안내 앱이 정상적으로 나타나는 지점까지 완성하는 것이 목표다.

---

## 15. 디자인 원칙

1. 게임 UI처럼 과장하기보다 실제 OS/업무용 플랫폼처럼 보여야 한다.
2. 처음부터 모든 것이 수상해 보이면 안 된다.
3. PROJECT ROOT 브랜드는 절제해서 사용한다.
4. 애니메이션은 짧고 부드럽게 사용한다.
5. 웹사이트임을 잊을 정도로 화면 전환이 자연스러워야 한다.
6. 데스크톱 진입 이후에는 일반적인 웹페이지 스크롤 구조를 최소화한다.
7. 반응형으로 만들되 데스크톱 플레이를 우선한다.

---

## 16. 장기 스토리 방향

초반에는 플레이어가 여러 사이버 사건을 해결한다.

사건들이 독립적으로 보이지만 시간이 지나면서 반복되는 인물, 계정, 서버, 로그 등의 연결점이 나타난다.

결국 플레이어는 자신이 사용하는 시스템과 자신을 고용한 조직에도 숨겨진 목적이 있다는 사실을 발견하게 된다.

특히 플레이어가 게임에서 수행한 검색, 터미널 사용, 저장한 정보 등의 기록 자체가 후반 스토리의 단서가 될 수 있다.

구체적인 후반 스토리는 초기 버전에서 UI에 노출하지 않는다.

### 플레이어 워크스테이션

PROJECT ROOT에서 플레이어가 사용하는 컴퓨터는
별도의 가상 브랜드 OS가 아니라 실제 Linux 환경을 기반으로 한다.

기본 환경:

- OS: Debian GNU/Linux
- Desktop Environment: KDE Plasma
- Terminal: Konsole
- File Manager: Dolphin

PROJECT ROOT의 Cases 등 게임 전용 프로그램은
이 Linux 환경에 설치된 사내 업무용 프로그램이라는 설정이다.

게임 내 터미널과 파일 시스템 역시 Linux의 구조와 명령 체계를
기준으로 설계한다.

단, 게임에서 제공되는 서버, 계정, 네트워크 및 침투 대상은
PROJECT ROOT 내부의 가상 환경으로 한정한다.
