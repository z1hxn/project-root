# [Project Root 사내 문서] 4-1 운영 기록 보존과 대조

문서 번호: PR-SEC-4-1 | 담당: 보안운영실 | 적용일: 2026-09-16 | 개정: 1.9 | 등급: 사내

## 기록의 성격
중앙 운영 기록은 여러 시스템이 각자의 시계와 형식으로 생성한다. 한 계정의 성공 응답은 자격 증명이 받아들여졌다는 뜻이며, 계정 소유자가 직접 조작했다는 증거는 아니다. 예약 작업의 실행 기록은 작업이 일어났다는 뜻이지 같은 날의 모든 접속을 설명하지 않는다. 서로 다른 출처의 로그를 교차 대조해야 한다.

## 저장과 시간 기준
개발 파일 서비스의 읽기 전용 `logs` 공유는 운영 조사에 필요한 원본 묶음을 보관한다. 폴더의 의미와 파일명 패턴은 개발팀 문서 3-1에 있다. 로그 안의 `+09:00`은 한국 표준시 오프셋이며, 비교할 때는 오프셋을 포함해 기록한다. `auth`의 일자별 파일은 파일명 날짜가 현지 날짜 기준이다. 파일을 내려받은 시각과 이벤트 시각을 혼동하지 않는다.

## 대조 순서
1. 대상 계정의 여러 날짜를 살펴 평소 출발지와 인증 방식의 범위를 만든다.
2. 검토 시각의 실패 및 성공 이벤트, 세션 식별자, 접속 서비스를 확인한다.
3. 같은 시간대의 scheduler, runner, API 요청을 확인해 자동화와 사람의 동작을 나눈다.
4. 서비스 계정의 토큰 인증과 개인 계정의 MFA/SSO 인증을 분리한다.
5. 공개 웹 기록이 연결될 경우 타임라인의 참고 자료로 쓰되 내부 접근의 주체를 단정하는 근거로 단독 사용하지 않는다.

원본 파일과 발췌본의 내용이 다를 때에는 필터링 범위, 수집 시각, 내보내기 조건을 먼저 확인한다. 사건 보고서에는 확인되지 않은 연결을 ‘가능성’으로 표시한다.

관련 문서: 1-2 조사 기록 작성, 3-1 개발 서비스, 4-2 계정 검토.
