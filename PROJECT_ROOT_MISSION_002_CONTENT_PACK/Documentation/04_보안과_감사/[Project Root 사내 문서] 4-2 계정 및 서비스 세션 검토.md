# [Project Root 사내 문서] 4-2 계정 및 서비스 세션 검토

문서 번호: PR-SEC-4-2 | 담당: 보안운영실 | 적용일: 2026-09-18 | 개정: 1.5 | 등급: 사내

## 계정 유형
개인 계정은 사람에게 배정되며 일반적으로 워크스테이션, MFA 또는 SSO 이력과 함께 나타난다. `svc-` 접두어 계정은 예약 작업이나 서비스 연동에 사용한다. 서비스 계정의 인증은 승인된 runner, 서비스 토큰, 정해진 작업 창과 함께 읽어야 한다. 두 유형을 같은 기준으로 판단하면 자동 작업을 사람의 로그인으로 잘못 분류할 수 있다.

## 검토 필드
| 필드 | 확인할 사항 |
| --- | --- |
| `account` | 개인 계정인지 서비스 계정인지 |
| `source` | 평소 사용하던 워크스테이션 또는 runner인지 |
| `service` | 접근한 서비스가 업무 흐름과 맞는지 |
| `method` | MFA, SSO, 서비스 토큰 등 인증 방식 |
| `session` | 전후 기록을 이어 주는 세션 식별자 |
| `result` | 실패 후 성공, 반복 시도, 단독 성공 여부 |

출발지가 바뀌었다고 곧바로 침해로 확정하지 않는다. 승인된 점프 호스트, 원격 근무, 임시 작업 창도 설명이 될 수 있다. 반대로 성공 이벤트 뒤의 API 요청이 특정 계정으로 기록되어도 실제 조작자를 확정하려면 별도의 검증이 필요하다.

## 점검 질문
- 검토 전 며칠 동안 같은 계정은 어디에서 로그인했는가?
- 같은 시간대에 서비스 계정의 정기 실행이 따로 존재하는가?
- 실패 이벤트와 성공 이벤트가 하나의 연속된 시도인가?
- 공개 변경 이력이나 게시물은 내부 기록의 시간 순서를 뒷받침하는가, 아니면 단순히 근접한 시각인가?
- 누가 승인 내역과 단말 기록을 추가 확인해야 하는가?

결론이 부족하면 ‘추가 확인 필요’로 남기고 부족한 자료를 적는다. 계정 소유자와 실제 접속자를 동일시하는 문장은 피한다.

관련 문서: 1-2 조사 기록 작성, 4-1 운영 기록 보존.
