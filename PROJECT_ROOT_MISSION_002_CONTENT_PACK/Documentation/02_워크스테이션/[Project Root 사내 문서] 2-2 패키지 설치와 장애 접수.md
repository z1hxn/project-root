## 패키지 관리 원칙
관리형 이미지에는 조사에 늘 필요한 기본 프로그램만 포함한다. 추가 도구는 Debian의 승인된 패키지 저장소에서 설치한다. 임의의 바이너리를 웹에서 내려받거나 관리자 설정 파일을 수정해 기존 접근 제약을 우회하지 않는다. 설치 전 `which 도구명`으로 존재 여부를 확인할 수 있다.

Samba 파일 공유를 명령행에서 확인할 때 필요한 패키지는 `smbclient`다. Konsole에서 패키지 목록을 갱신한 뒤 설치한다.

```sh
sudo apt update
sudo apt install smbclient
which smbclient
```

위 절차는 SMB 공유에 대한 접근 권한을 새로 부여하지 않는다. 패키지가 있어도 서버의 공유 정책이나 계정 권한 때문에 접속이 거부될 수 있다. 반대로 Dolphin에 SMB KIO worker가 없더라도 `smbclient`는 별도 실행 파일이므로 명령행 접속은 가능하다.

## 장애를 구분하는 방법
- `command not found`: 실행 파일이 없거나 PATH에서 찾지 못했다. 설치 상태를 확인한다.
- 호스트를 찾을 수 없음: 주소 철자와 내부 서비스 목록을 먼저 확인한다.
- `NT_STATUS_BAD_NETWORK_NAME`: 공유 이름 또는 서버가 제공하는 서비스 종류를 확인한다.
- `NT_STATUS_ACCESS_DENIED`: 지정된 계정의 권한 문제다. 다른 사람의 계정을 대신 사용하지 않는다.
- 파일을 찾을 수 없음: 원격 현재 디렉터리와 상대 경로를 다시 확인한다.

장애 접수에는 실행한 도구, 대상 호스트·공유, 오류 문구, 시각을 적되 비밀번호나 토큰을 붙이지 않는다. 보안 정책 변경 요청과 프로그램 고장 신고를 구별한다.
